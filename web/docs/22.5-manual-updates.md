- **Important operational finding:** `vercel env rm NAME production` on a variable with one binding shared across Production+Preview deletes it from **both** environments, not just the target one (confirmed by testing on `TERMS_VERSION`). Any future edit to one of these 53 now-split variables is safe (each side is now an independent binding), but if a new *shared* variable is ever added again, split it the same way: know both values in advance (or accept regenerating both) before touching `rm`.
